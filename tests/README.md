# Test rationale

The suite uses parameters that isolate a contract boundary or make ordering
deterministic. They are not production retrieval-quality targets. This document
records the rationale for tests added or materially refined during the contract
test expansion.

## Built-in ingestion handlers

| Test | What it protects | Parameter rationale |
| --- | --- | --- |
| `test_pdf_loader_reports_pages_and_empty_pages` | PDF routing, page accounting, document metadata, and source provenance | A one-page blank PDF is generated in memory with `pypdf`; it deterministically exercises the empty-page path without checking parser-specific text layout, while title and author verify useful metadata extraction. |
| `test_pdf_loader_extracts_text_with_a_page_label` | Embedded PDF text is extracted and retains its human-readable page reference | A minimal one-page Helvetica PDF contains a single unique phrase, avoiding layout ambiguity while exercising the real `pypdf` parser. |
| `test_default_pipeline_ingests_supported_file_paths` | PDF, TXT, CSV, and HTML all work through the filesystem entry point | One minimal file per requested format verifies suffix routing, extracted text, and `source_path` provenance without involving retrieval ranking. |
| `test_text_normalization_handles_unicode_cr_and_outer_blank_lines` | NFC normalization, classic-Mac newlines, trailing spaces, and outer blank removal | A decomposed `e` + acute accent proves NFC composition; `\r` isolates CR conversion from the already-covered CRLF case; two outer CRs prove blank trimming without changing internal prose. |
| `test_json_loader_preserves_unicode_and_reports_non_object_roots` | Readable Unicode and correct root metadata for JSON arrays | A two-item array is the smallest non-object root containing both Unicode text and a nested object; `42` is a stable scalar with no formatting ambiguity. |
| `test_json_loader_rejects_malformed_input` | Invalid structured data is not silently indexed | `{"broken":` is valid enough to enter JSON parsing but necessarily incomplete, producing the standard `JSONDecodeError`. |
| `test_csv_loader_handles_empty_input` | Empty input has zero rows and columns | `b""` is the actual empty-file boundary; no fabricated header or row should appear. |
| `test_csv_loader_handles_bom_blank_headers_and_uneven_rows` | BOM decoding, fallback headers, and short/long rows | One blank header triggers `column_2`; a four-cell row against three headers triggers `column_4`; a two-cell row proves missing-cell padding. The final expectation ends at `role:` because global normalization intentionally removes trailing whitespace. |
| `test_html_loader_preserves_entities_and_block_boundaries` | Visible entities and paragraph/break structure while skipped elements stay hidden | `&amp;` exercises entity decoding, `<br/>` the self-closing block path, and `template`/`svg` two separate skipped-content categories. |

## Document pipeline

| Test | What it protects | Parameter rationale |
| --- | --- | --- |
| `test_cleaner_prepend_and_replace_control_the_type_specific_chain` | Exact semantics of `prepend=True` and `replace=True` | Appending `A`, prepending `B`, then replacing with `C` makes order observable as `0BA` and replacement observable as `0C`; single characters avoid text-normalization effects. |
| `test_loader_must_preserve_the_resolved_document_type` | A dispatched loader cannot relabel its result | Registered `txt` returning `pdf` is the smallest unambiguous mismatch and verifies both sides of the error message. |
| `test_cleaner_must_return_a_document` | Cleaner output obeys the canonical model contract | A plain string is callable output but not a `Document`, isolating result validation from invocation failure. |
| `test_cleaner_must_preserve_the_document_type` | Cleaners cannot change routing identity | `txt` to `pdf` is a clear type mutation while leaving the text valid. |
| `test_source_arguments_reject_ambiguous_or_unsupported_inputs` | Provenance cannot be supplied twice, and invalid source classes fail early | A `DocumentSource` plus metadata tests duplicate provenance; a path plus `name` tests conflicting filesystem identity; integer `42` is neither bytes, path, nor `DocumentSource`. |

## Existing modular RAG tests refined

| Test | Refinement | Parameter rationale |
| --- | --- | --- |
| `test_demo_factory_accepts_a_pipeline_with_a_new_format` | Moved from `ChunkerTests` to `FactoryIntegrationTests` and documented | No runtime parameter changed; the move fixes ownership because the test exercises composition and injection, not chunk boundaries. |
| `test_replacement_removes_old_chunks_without_touching_other_documents` | Replaced the unsupported “atomic” claim with assertions for stale-chunk removal and document isolation | Existing 2D vectors and `top_k=5` were retained: 2D makes cosine order obvious, and five is safely above the three possible records so truncation cannot hide stale data. |
| `test_demo_pipeline_indexes_retrieves_answers_and_cites` | Added chunk-count, result-count, citation-count, marker, and excerpt checks | Existing `max_words=20` and overlap `3` were retained so both short sentences form one evidence chunk; this isolates wiring and citation fidelity from ranking across chunks. |
| `test_reindex_and_delete_remove_stale_evidence_end_to_end` | Added application-level replacement and deletion coverage | `max_words=10` fits each five-word version in exactly one chunk; overlap `0` removes overlap as a confounder; the same `document_id` is required to exercise replacement. |
| `test_hashing_embedder_is_deterministic_normalized_and_input_sensitive` | Strengthened same-input equality with dimension, norm, different-input, and empty-input assertions | Dimension `32` was retained because it is small and fast while giving the two chosen token sets ample room to avoid a contrived collision; unit norm is the cosine-search contract, while empty text must remain the zero vector. |

## Core contract tests

| Test | What it protects | Parameter rationale |
| --- | --- | --- |
| `test_chunker_rejects_invalid_window_configuration` | Constructor boundaries and guaranteed forward progress | `max_words=0` is the nonpositive boundary; overlap `-1` is the first negative value; overlap `4` equals a four-word window and would make the step zero; overlap `3` proves the largest valid value. |
| `test_chunker_generates_stable_source_based_document_ids` | Fallback IDs are deterministic and provenance-sensitive | Four words with window `3` and overlap `1` must start at words `0` and `2`; identical text under two source names proves provenance participates in identity. |
| `test_rejected_replacements_preserve_existing_records` | Store validation occurs before mutation | A valid 2D record is challenged by a wrong owner, a mixed 2D/3D batch, and an all-3D incompatible replacement; querying 2D afterward proves the original survived each failure. |
| `test_deleting_the_last_document_resets_vector_dimension` | Empty stores can migrate embedding dimensions | The change from 2D to 3D is the smallest visible dimension migration and occurs only after deletion of the sole document. |
| `test_search_supports_reserved_filters_and_deterministic_ties` | Reserved ID filters and stable tie-breaking | Two equal unit vectors force a score tie; reverse insertion order proves sorting uses chunk IDs; `top_k=2` includes both, and combined document/chunk filters select exactly one. |
| `test_search_rejects_nonpositive_top_k` | Invalid result limits fail explicitly | `0` tests the empty boundary and `-1` the negative domain. |
| `test_indexer_rejects_an_empty_chunk_sequence` | A processed document cannot report success with no evidence | An eight-dimensional embedder is a cheap valid collaborator but is intentionally never called; the empty tuple isolates the chunker contract. |
| `test_indexer_rejects_chunks_with_multiple_document_ids` | One replacement cannot mix document owners | Two chunks are the minimum sequence that can disagree; IDs `a` and `b` make the mismatch direct. |
| `test_indexer_updates_and_deletes_auxiliary_document_indexes` | Optional indexes follow primary replacement/deletion lifecycle | Window `10` with overlap `0` forces the three-word document into one chunk; dimension `8` keeps hashing cheap while remaining a valid nonempty vector. |
| `test_hashing_embedder_rejects_nonpositive_dimensions` | Embeddings always have at least one coordinate | `0` is the empty-vector boundary and `-1` covers the negative domain. |
| `test_structural_verifier_receives_the_answer_and_exact_contexts` | Third-party answer verifiers satisfy the protocol structurally and receive the generated answer plus its evidence unchanged | One result is the smallest nonempty evidence set; distinct `question` and `answer` strings make argument order observable, while score `0.9` is data forwarded to the adapter rather than a verification threshold. |
| `test_verification_result_validates_fields_and_snapshots_metadata` | Verification verdicts remain unambiguous and their top-level diagnostics cannot change through the caller's original mapping | `False` exercises an unsupported verdict; integer `1` must not masquerade as a boolean, `None` is the smallest invalid reason, and a single metadata key is sufficient to prove defensive copying. |
| `test_service_rejects_invalid_default_limits` | Service defaults are positive and fetch covers final selection | `(0,1)` invalidates final count, `(1,0)` invalidates fetch count, and `(3,2)` uses positive values but violates `fetch >= final`. |
| `test_service_rejects_invalid_requests_and_method_registrations` | Questions, per-call limits, method types, reserved names, and normalized duplicates are validated | Whitespace isolates empty text; `top_k=0` is the boundary; integer `7` is non-string; padded/case-varied method names prove validation happens after normalization. |
| `test_reranking_fetches_more_candidates_than_it_returns` | Candidate breadth and final response size remain separate | Fetch `4` and final `2` are deliberately different and small; reversing four candidates makes it observable that reranking saw all four before two were returned. |
| `test_citations_normalize_excerpts_and_apply_source_fallbacks` | Citation numbering, readable excerpts, and provenance fallback | Two results are the minimum for numbering; scores `0.9` and `0.8` keep their order deterministic but are not acceptance thresholds; missing source metadata on the second result forces document-ID fallback. |
| `test_qasc_configuration_requires_explicit_enablement` | Optional indexing cost cannot be activated accidentally | Segmenter-only and config-only cases cover both optional arguments independently while leaving `enable_qasc` at its explicit default `False`. |
| `test_component_type_errors_are_not_mislabeled_as_bad_sequences` | Internal adapter bugs retain their original exception instead of being reported as malformed return values | A retriever and reranker each raise `TypeError` inside their call; separate cases distinguish invocation from the tuple-conversion boundary. |
| `test_generator_must_return_nonempty_text` | Empty model output cannot become a successful response | Both an empty string and whitespace-only text exercise the semantic boundary while valid evidence keeps generation on the active path. |
| `test_rejects_malformed_model_revisions_at_construction` | Dense-model revision identity fails early and predictably | Integer `123` covers the wrong type and three spaces cover a present but empty revision without loading model weights. |

## Public models and indexing adapter boundaries

| Test | What it protects | Parameter rationale |
| --- | --- | --- |
| `test_metadata_snapshots_mutable_byte_buffers_as_bytes` | Domain metadata cannot retain mutable byte-buffer aliases | One `bytearray` and one `memoryview` are mutated after constructing four metadata-bearing models; the scalar list covers every allowed built-in scalar, including immutable `bytes`. |
| `test_metadata_rejects_values_outside_the_builtin_domain` | Metadata is limited to recursively snapshot-safe built-ins with string mapping keys | A custom mutable object appears both at the top level and nested in a list, while integer key `1` isolates the key-type rule. |
| `test_public_model_text_fields_require_non_whitespace_strings` | Identity and user-facing text fields cannot be silently coerced or blank | Every protected string field is tested with `True`, integer `1`, float `1.0`, and whitespace; these separate wrong-type errors from semantic emptiness. |
| `test_public_model_integer_fields_reject_bool_float_and_bad_ranges` | Positional/count fields accept real integers only and retain their individual bounds | Boolean and `1.0` exercise Python numeric impostors for six fields; `-1` checks nonnegative fields, `0` checks positive fields, and valid zero/one boundary examples prevent over-rejection. |
| `test_vector_record_requires_a_chunk` | A vector cannot legitimize evidence without a canonical `Chunk` | `object()` with a valid one-coordinate vector isolates the chunk-type boundary. |
| `test_search_result_requires_a_chunk` | Retrieval evidence fails at construction when its chunk is malformed | `object()` paired with finite score `0.8` isolates chunk validation from score validation. |
| `test_evidence_metadata_is_a_deep_immutable_snapshot` | Nested caller mutations cannot rewrite stored evidence or verification diagnostics | One nested list, set, and mapping are mutated after construction across four model types; tuple, frozenset, and read-only mapping assertions cover each normalized container. |
| `test_rag_response_snapshots_typed_containers_and_aligns_citations` | Responses own stable tuples and enforce one-to-one citation/result identity, order, and score | One valid pair proves list snapshotting; wrong question/answer types, wrong member types, missing citation, and mismatched chunk ID cover distinct failure modes with the smallest response. |
| `test_hashing_embedder_rejects_non_integer_dimensions` | Hash vector shape cannot be configured through Python's boolean/inexact numeric coercions | `True` covers bool-as-int and `8.0` covers a numerically integral but wrongly typed float. |
| `test_indexer_rejects_forged_canonical_document_id_before_embedding` | A chunker cannot redirect a canonical document write to another owner by mutating its adapter input | The replaceable chunker mutates its `Document` metadata from canonical ID `guide` to `forged` before returning the forged chunk; comparison with the pre-callback snapshot must reject it, and a counting embedder at zero calls proves rejection precedes embedding and storage. |
| `test_indexer_rejects_missing_or_changed_protected_chunk_metadata` | Repository provenance required by the indexer survives chunking exactly | Changing `relative_path` and removing `document_state_token` cover alteration and omission; a no-op mutation proves the same four-field metadata set is accepted. |
| `test_max_chunks_requires_a_positive_non_boolean_integer` | Per-document chunk limits reject lossy types and invalid ranges before work begins | `True`, `False`, `1.0`, and `"1"` cover type hazards; `0` and `-1` cover range boundaries; valid `1` admits the single test chunk. |
| `test_chunker_result_boundary_rejects_non_iterables_and_non_chunks` | Malformed chunker returns fail clearly before dereference or publication | `None` and `42` are non-iterable; a string item and a chunker object are iterable/non-`Chunk` cases at position zero. |
| `test_lazy_chunker_type_error_propagates_from_adapter_iteration` | A chunk generator's internal failure is not mislabeled as non-iterability | The generator yields one valid chunk before raising a distinctive `TypeError`, proving iteration-time errors preserve adapter context and publish nothing. |
| `test_embedder_result_boundary_distinguishes_non_iterable_and_lazy_failure` | Embedder return-shape errors remain distinct from failures while consuming a valid iterator | `None` and `42` cover failure to obtain an iterator; a generator yields one vector then raises `TypeError`, and all cases leave storage empty. |
| `test_indexer_constructs_vector_records_to_validate_each_vector` | Every embedder vector crosses the canonical numeric model boundary before storage | Scalar `1`, text `"bad"`, empty tuple, boolean coordinate, and `NaN` separately exercise sequence, emptiness, coercion, and finiteness checks on one returned vector. |
| `test_delete_requires_a_nonempty_string_document_id` | Public deletion rejects ambiguous identities before any adapter call | `None`, bytes, integer, and boolean cover wrong types; empty and whitespace strings cover semantic emptiness while event/state assertions prove no write started. |
| `test_word_and_code_chunkers_require_real_integer_window_limits` | Word and code window geometry cannot be configured with booleans, floats, or strings | Both chunkers test each maximum/overlap field with boolean, integral float, and numeric string values, covering the symmetric type boundary. |
| `test_word_and_code_chunkers_keep_range_failures_as_value_errors` | Correctly typed but impossible windows retain clear range errors | Each chunker receives maximum `0`/`-1`, overlap `-1`, overlap equal to `4`, and overlap `5`; equality catches zero progress and five catches overshoot. |
| `test_rejects_coercible_and_overflowing_embedding_coordinates` | Dense adapters reject nonnumeric backend coordinates rather than accepting `float(...)` impostors | Boolean, numeric string, numeric bytes, and an object whose `__float__` overflows cover coercible and overflow paths in a one-vector fake backend. |

## Multi-index replacement

| Test | What it protects | Parameter rationale |
| --- | --- | --- |
| `test_all_replacements_are_prepared_before_the_first_commit` | Coordinated writes stage every participant before publishing any new state | Two auxiliary indexes are the smallest composition that proves ordering across more than one auxiliary; one-dimensional unit vectors and one chunk keep the event sequence independent of retrieval quality. |
| `test_auxiliary_prepare_failure_preserves_every_previous_version` | A staging failure cannot publish a mixed old/new document version | Three auxiliaries let `failing_index=0,1,2` cover first, middle, and last prepare positions; distinct `old version` and `new version` text makes state drift visible. |
| `test_auxiliary_commit_failure_rolls_back_every_previous_version` | A commit that mutates and then raises restores all participants to the prior version | Injecting failure at each of three auxiliary positions exercises rollback before, at, and after other auxiliary commits; a deliberately mutating failure tests restoration rather than mere discard of staged state. |
| `test_multi_index_composition_rejects_each_legacy_participant` | Multi-index writes cannot begin unless every participant supports prepare/commit/rollback coordination | One case omits staging on the primary store and one on auxiliary index `0`, covering both participant roles with the smallest multi-index composition; empty event/state assertions prove rejection happens at construction. |
| `test_single_store_indexing_keeps_the_original_write_contract` | Primary-only indexing remains compatible with stores that expose only the original replacement API | No auxiliary indexes selects the compatibility path; a single chunk and one-dimensional vector are sufficient to prove `replace_document` still receives and publishes the record. |
| `test_real_store_and_qasc_preserve_old_version_on_qasc_prepare_failure` | The concrete in-memory store and QASC adapter remain aligned when QASC staging fails | `window_radius=0` reduces one sentence to one QASC window; an injected segmenter failure and distinct old/new text isolate preparation failure while verifying both real indexes retain the old version. |
| `test_auxiliary_delete_failure_restores_every_participant` | A prepare or commit failure during deletion cannot divide primary and auxiliary state | Three auxiliaries and both failure phases cover first, middle, and last positions; one existing document makes full restoration observable in every participant. |
| `test_shared_coordinator_hides_intermediate_component_commits` | Participating readers cannot observe the primary new version while QASC remains old | One blocked auxiliary commit creates the exact vulnerable interval; a reader-start event proves the query attempted during that interval, while a 50 ms bounded wait checks it remains blocked without making wall-clock speed a performance assertion. |
| `test_commit_interruption_rolls_back_before_propagating` | Process-control exceptions cannot strand a partially published generation | A commit mutates and raises `KeyboardInterrupt`; the exception must propagate only after every prepared participant returns to the old version. |
| `test_permanent_failure_matrix_restores_every_participant` | Replace and delete transactions recover from ordinary and process-control failures at every preparation and commit position | Two operations, two stages, five participant positions, and `RuntimeError`/`KeyboardInterrupt`/`SystemExit` form 60 explicit subtests; distinct old/new text makes any partial publication visible. |
| `test_atomic_composition_requires_exact_coordinator_on_every_participant` | Configured participants cannot join one transaction under missing or different coordinator ownership | Primary plus two auxiliaries cover every position; deleted, `None`, and foreign coordinator bindings cover absent, null, and mismatched ownership before any event occurs. |
| `test_additional_participant_requires_primary_coordinator_ownership` | A legacy primary store is accepted alone but rejected before a dynamically coordinated write begins | One additional preparation is sufficient to activate coordination; a boolean flag proves the callback is never invoked when the primary lacks ownership. |
| `test_dynamic_handles_reject_invalid_unbound_and_mismatched_results` | Runtime-supplied replacement/delete handles must be complete and bound to the active coordinator | Replace and delete each test a missing rollback plus missing, `None`, and foreign coordinator markers; one auxiliary and an old version make rollback/no-commit behavior observable. |
| `test_primary_only_legacy_store_delete_keeps_original_contract` | Direct deletion remains backward-compatible for a primary-only legacy store | The fake returns deletion count `3`, a distinctive nonzero value that proves the indexer forwards the original method result and exact `guide` ID. |
| `test_transaction_protocols_are_structural_and_coordinator_aware` | Public runtime-checkable protocols recognize duck-typed adapters and coordinated handles | One store, one auxiliary, and one handle are the minimum instances needed to check all three protocols and identity with the indexer's coordinator. |
| `test_qasc_cannot_publish_under_a_forged_document_owner` | A QASC segmenter cannot split auxiliary evidence from the canonical document lifecycle by mutating its adapter input | The replaceable segmenter mutates its `Document` metadata from canonical owner `guide` to `forged` before returning the span; the pre-callback snapshot must reject it and leave both indexes empty, while disabling the mutation proves one accepted replacement and coordinated deletion. |
| `test_real_store_and_qasc_handles_are_idempotent` | Built-in store and QASC replacement/deletion handles tolerate duplicate commit and rollback calls | Both operation types run across both real participants; calling each transition twice proves idempotence while `window_radius=0` keeps QASC evidence to one window. |
| `test_real_store_and_qasc_stale_handles_cannot_clobber_a_winner` | Stale built-in replacement and deletion handles cannot overwrite or remove a newer generation | Competing handles for `stale`, `winner`, and `newer winner` cover both operation directions in store and QASC; repeated rollback proves stale cleanup is harmless. |

These tests cover replacements and deletions coordinated through one `Indexer`.
The shared coordinator provides in-process visibility isolation. It does not
claim process-crash durability, cross-process isolation, or safety for custom
writers that bypass the configured transaction mechanism.

## Vector boundary validation

| Test | What it protects | Parameter rationale |
| --- | --- | --- |
| `test_replacement_rejects_empty_non_finite_and_malformed_vectors` | The in-memory store validates replacement vectors before changing existing state | Empty, `NaN`, positive/negative infinity, a nonnumeric coordinate, and a non-iterable object cover distinct invalid shapes; a valid 2D record and matching query prove each rejection preserves the previous record. |
| `test_replacement_rejects_duplicate_and_cross_document_chunk_ids` | Mapping-key collisions cannot silently drop a replacement chunk or overwrite another document | Two same-document records share one ID for the duplicate case; a second document then attempts to reuse an existing ID, and the original one-record state must survive both failures. |
| `test_replacement_rejects_mixed_dimensions_and_accepts_valid_vectors` | Store replacement batches are rectangular without rejecting ordinary finite numeric vectors | A 2D/3D pair is the smallest mixed batch; orthogonal 2D vectors and query `(1, 0)` make the accepted cosine order deterministic, while `top_k=2` returns both records. |
| `test_search_rejects_empty_non_finite_malformed_and_wrong_dimension_vectors` | Invalid store queries fail before cosine scoring | Empty, `NaN`, infinity, and a nonnumeric coordinate cover validation classes; a 1D query against a 2D index is the smallest dimension mismatch, and `top_k=1` keeps result-count behavior out of scope. |
| `test_competing_prepares_reject_the_stale_store_commit` | A prepared store snapshot cannot overwrite a state committed from the same starting point | Two prepared replacements are the minimum lost-update race; committing the first and rejecting the second makes the winning record unambiguous, while repeated rollback checks idempotence. |
| `test_store_rollback_does_not_clobber_an_intervening_write_or_delete` | Stale store rollback neither resurrects deleted evidence nor removes a newer document | One committed candidate, one newer document, and one effective delete are the smallest sequence that changes state ownership before two rollback calls. |
| `test_store_cosine_stays_finite_for_extreme_finite_coordinates` | Store scoring cannot turn valid finite coordinates into a `NaN` result through overflow | Matching two-dimensional `1e308` vectors are finite but make naive squaring overflow; expecting a cosine near `1.0` verifies the scaled calculation. |
| `test_sentence_index_rejects_empty_non_finite_and_malformed_vectors` | QASC validates the full sentence-embedding batch before replacing its prior index | Two sentence spans permit one invalid vector beside one valid vector; empty, all non-finite variants, a bad coordinate, scalar outer entry, and `None` cover coordinate, vector, and batch malformation while a preloaded valid index proves failure preservation. |
| `test_sentence_index_rejects_mixed_dimensions_and_accepts_valid_vectors` | QASC requires rectangular sentence vectors and still accepts finite numeric inputs | One 2D and one 3D vector form the smallest mismatch; replacing them with integer unit vectors proves numeric coercion, two sentences, and successful retrieval without depending on model output. |
| `test_query_rejects_empty_non_finite_malformed_and_wrong_dimension_vectors` | QASC queries obey the same numeric and dimension contract as sentence vectors | Empty, `NaN`, infinity, and a bad coordinate cover the invalid numeric classes; a 1D query against the valid 2D sentence index isolates dimension checking, with `top_k=1` avoiding ranking breadth as a confounder. |
| `test_competing_prepares_reject_the_stale_qasc_commit` | A stale QASC handle cannot replace a newer published sentence index | Two handles prepared from one base version reproduce the race with the fewest candidates; distinct metadata labels identify which version remains visible. |
| `test_qasc_rollback_does_not_clobber_an_intervening_write_or_delete` | QASC rollback preserves the state owned by a later replacement and deletion | A two-sentence guide, one newer document, and deletion of the guide prove stale rollback cannot restore an obsolete whole-index snapshot. |
| `test_qasc_scores_stay_finite_for_extreme_finite_coordinates` | QASC sentence scoring and aggregation stay finite near the float limit | Matching two-dimensional `1e308` vectors reproduce naive square overflow while still having an exact expected cosine near `1.0`. |
| `test_vector_record_rejects_non_finite_and_non_numeric_coordinates` | Invalid vectors fail at the domain-model boundary before reaching adapters | `NaN`, both infinities, boolean, numeric string, top-level string, and non-iterable object cover finite, type-coercion, and sequence-shape hazards with the smallest one-coordinate inputs. |
| `test_result_and_citation_scores_must_be_finite_numbers` | Retrieval and citation models cannot transport corrupt ranking scores | Both infinities, `NaN`, boolean, and numeric string cover invalid score forms; finite score `-0.25` proves negative calibrated score domains remain valid. |
| `test_document_state_token_requires_present_consistent_chunk_metadata` | Store reuse identity is exposed only when every chunk in the document carries one common token | Two chunks with the same 64-character token establish the positive case; a direct tokenless replacement and a missing ID both return `None`. |
| `test_many_replacements_and_token_reads_do_not_scan_the_global_record_map` | Per-document store updates and state-token lookups stay locally bounded | A dictionary that raises on iteration/copy makes global scans deterministic failures; 200 documents and deletion of every second document exercise growth, lookup, and shrinkage while retaining the same global map object. |
| `test_search_top_k_requires_a_non_boolean_integer` | Store search limits reject Python numeric impostors before ranking | `True` covers bool-as-int and `1.0` covers an integral float against a valid one-record index. |

## Relevance and abstention

| Test | What it protects | Parameter rationale |
| --- | --- | --- |
| `test_empty_retrieval_abstains_before_generation` | Missing evidence returns the service-owned abstention without invoking generation | An empty result tuple is the exact no-evidence boundary; empty results, citations, and generator calls verify a clean short circuit. |
| `test_all_zero_scores_at_default_boundary_abstain_before_generation` | The default relevance floor is an exclusive `> 0.0` check | Two `0.0` results prove equality at the boundary is consistently rejected rather than relying on a single-item special case. |
| `test_only_relevant_results_reach_generation_and_citations` | The default gate removes nonpositive evidence while preserving a positive hit through generation and citation creation | Scores `0.8`, `0.0`, and `-0.2` represent accepted, boundary, and below-boundary cases; one survivor makes generator arguments and citation renumbering unambiguous. |
| `test_negative_reranker_score_does_not_reuse_retrieval_threshold` | A candidate accepted in the retriever's score domain is not discarded when a reranker emits a valid negative score | Retrieval score `0.8` clears the default floor; reranker score `-0.1` proves domains stay separate; `default_top_k=1` and `default_fetch_k=3` keep candidate breadth distinct from final selection. |
| `test_method_specific_threshold_supports_backend_calibration` | A normalized query method can select an injected backend-specific threshold | QASC floor `-0.5` accepts score `-0.25`, while the default `0.0` floor rejects that same result; asking with uppercase `QASC` also proves case-normalized method lookup. |

## CI gates

Every CI lane first constrains pip to `>=24,<27`, avoiding the verified legacy
pip behavior that builds this PEP 621 project as `UNKNOWN-0.0.0`. The core
Python 3.9/3.14 matrix then checks installed dependency consistency and compiles
every source module before running the full behavioral suite and end-to-end
example. These gates are intentionally dependency-free after package
installation and catch metadata conflicts or syntax failures earlier.

The `spacy-adapter` job installs `.[spacy]` and runs only
`test_sentence_segmentation.py` on Python 3.9 and 3.14. The project declares
interpreter-specific spaCy ranges, so both supported endpoints are exercised.
The ten-minute timeout matches the core test job
and provides installation headroom without permitting a hung optional job.

The code-parser matrix likewise exercises Python 3.9 and 3.14. A separate
wheel-smoke job builds and installs the package, then checks distribution
metadata and public imports from outside the checkout so source files cannot
mask missing wheel contents.
